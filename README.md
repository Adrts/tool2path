## 项目简介

**tool2path** 是一个面向 Windows 的桌面小工具，用来统一登记并启用开发/运维机器上的**工具链可执行入口目录**（如 `C:\Program Files\nodejs`、`C:\Python312\Scripts`、`C:\Go\bin`），并把选中的目录写入 **用户级 PATH**（`HKCU\Environment\Path`）。

它的定位不是"环境变量编辑器"，而是一个**以外部配置文件为唯一事实源的 PATH 管理器**：

- **一个配置文件 = 一份报备清单**。清单存在与程序同级的 `registered-paths.yaml` 里，纯路径列表，可以随手用编辑器改、可以放进 dotfiles / Git 仓库随身走。
- **图形界面只是这份清单的可视化编辑器**。界面上所有增、删、改、排序都会即时写回该文件，保证"文件即界面"。
- **不报备，就不敢动**。只有登记在配置文件里的路径才允许被移动 / 移出 / 多选；系统原有且未报备的路径作为只读"锚点"，**相对顺序永远不变**。
- **改动集中在一次落盘**。界面的 PATH 改动先进入"待应用变更"，点「应用」时一次性全量写回注册表并广播 `WM_SETTINGCHANGE`，普通权限即可完成。

### 主要功能

| 功能 | 说明 |
| --- | --- |
| 报备清单管理 | 弹窗选择 / 多行粘贴目录批量报备；同目录自动去重；显示名由路径末级自动派生 |
| 三区工作台 | 左栏「报备库」— 中栏「移入 / 移出」— 右栏「PATH 总览」 |
| 库内自由排序 | 左栏任意拖拽排序，顺序实时写回配置文件（不进入待应用） |
| 双向跨栏拖拽 | 左→右 = 拖到哪落到哪（移入）；右→左 = 拖回即移出 |
| 批量操作 | 左右栏均支持多选 / 框选 / `Ctrl+A`；批量操作**保持组内相对顺序** |
| 锚点保护 | 未报备路径锁定只读：不可勾选、不可拖动、不可删除 |
| 待应用 + 撤销 | 右栏改动先入内存，`Ctrl+Z` 撤销单条 / 整组；落盘前自动校验锚点不变量 |
| 目录软校验 | 目录不存在 / 被移动时标黄提示，仍保留记录并支持一键重设 |
| 外部改动感知 | 配置文件被外部编辑器修改时提示是否重新载入，不自动覆盖界面状态 |
| 安全写回 | 保持 `REG_EXPAND_SZ` / `REG_SZ` 原类型、不做 `%VAR%` 展开、不使用 `setx`、超长（约 32000 字符）二次确认 |

## 它解决什么问题

开发者机器上通常装着 Node、Python、JDK、Go、FFmpeg、Git 等一堆工具链，每个工具链都有一个"可执行入口目录"，而调用哪个版本完全取决于 PATH。现实中的痛点与本期方案：

| 痛点 | 具体表现 | tool2path 的解决方式 |
| --- | --- | --- |
| **管理零散** | 入口目录散落在安装目录、SDK 目录、本地 `bin`，没有统一视图 | 所有入口目录集中登记在一个 `registered-paths.yaml` 里，左栏一览无余 |
| **切换困难** | 不同项目需要不同版本 / 不同启用组合，手改 PATH 又慢又易错 | 报备一次，之后勾选即"移入 / 移出"，随时切换启用组合 |
| **配置不透明** | 清单锁在某个软件的私有数据库里，看不到、改不动、无法版本管理 | 清单就是一个人人可读的 YAML 文本，可手工编辑、可纳入 Git / dotfiles |
| **误删误动风险** | 直接编辑 PATH 容易误删系统关键路径（如 `System32`），导致环境不可用 | 未报备路径是**只读锚点**，软件拒绝任何排序 / 移动 / 删除；落盘前再做一次锚点不变量断言 |
| **改动难以回退** | 一旦写进注册表，改错了很难恢复原状 | 改动先进"待应用变更"，`Ctrl+Z` 可撤销；只有点「应用」才真正落盘 |
| **写入不规范** | 用 `setx` 会截断长 PATH、把 `REG_EXPAND_SZ` 降级成 `REG_SZ`，`%VAR%` 丢失语义 | 遵循 Microsoft 标准做法：保持原类型、不展开变量、整键全量写回、广播 `WM_SETTINGCHANGE` |

**非目标**：不做通用环境变量编辑器、不做系统级（HKLM）PATH 管理、不做自动化探测已安装工具链、不做云端同步。

## 核心概念

| 术语 | 含义 |
| --- | --- |
| **报备（Registered）** | 把某个入口目录写入 `registered-paths.yaml`，即成为"可管理项" |
| **报备库** | 配置文件所代表的路径清单，即左栏视图（左栏只展示其中**尚未加入 PATH**的条目） |
| **入口目录（Entry dir）** | 存放可执行文件、需要被写入 PATH 的目录，也是配置文件中的每一行 |
| **锚点（Anchor）** | PATH 中未报备、系统原有的路径；只读，**相对顺序永不变** |
| **移入 / 移出** | 把报备项加入用户级 PATH / 从 PATH 中移除（移出后仍留在报备库，随时可再移入） |
| **报备即接管** | 报备一个"本来就在 PATH 中"的目录后，该行立即转为可管理项，不会重复追加 |
| **待应用变更** | 尚未写回注册表的内存态改动；`Ctrl+Z` 可撤销，点「应用 / 确认」后落盘 |

## 安装步骤

### 环境要求

- **操作系统**：Windows 10 / 11（核心功能依赖 Windows 注册表与 `WM_SETTINGCHANGE` 广播）。
  - 非 Windows 平台可启动程序并在内存中预览，但不会真正写入注册表（`WindowsRegistry` 回落为内存假实现），仅供开发与测试。
- **Python**：3.10 或更高版本（推荐 3.12+；开发与测试使用 3.14）。
- **权限**：普通用户权限即可，**无需管理员 / UAC**（只写 `HKCU\Environment\Path`）。
- **依赖**：仅 [PySide6](https://pypi.org/project/PySide6/) ≥ 6.9。

### 1. 获取源码

```powershell
git clone https://github.com/Adrts/tool2path.git
cd tool2path
```

### 2. 创建工程内虚拟环境（与系统环境剥离，推荐）

```powershell
py -3.14 -m venv .venv
# 若本机没有 3.14，可用已安装的版本，例如：
# py -3.12 -m venv .venv
```

> ⚠️ **虚拟环境目录名必须为 `.venv`**（命令中的最后一段即目录名）。这是启动脚本 [run.bat](./run.bat) 的硬性要求：脚本按固定相对路径 `.venv\Scripts\python.exe` 查找解释器，名称不一致会直接报错退出。若你只打算手动敲命令运行、不使用启动脚本，则目录名可任意。

### 3. 安装依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 4. 运行

**方式一：启动脚本（推荐，双击即可）**

直接双击工程根目录下的 [run.bat](./run.bat)，脚本会自动切到自身所在目录，并用 `.venv\Scripts\python.exe` 运行主程序。

> ⚠️ **本启动脚本必须搭配虚拟环境使用，且虚拟环境目录名必须为 `.venv`**（与第 2 步创建的目录保持一致）。脚本不依赖系统 PATH 中的 `python`，也不做任何环境回退：找不到 `.venv\Scripts\python.exe` 时会打印错误并退出（退出码 `1`）。

**方式二：命令行手动运行**

```powershell
.\.venv\Scripts\python.exe tool2path.py
```

### 5. 运行自测（可选，零额外依赖）

```powershell
.\.venv\Scripts\python.exe tests\selftest.py
```

退出码为 `0` 表示全部通过；脚本会逐项打印 `PASS` / `FAIL`，覆盖设计规则 R0–R7 与 GUI 离屏冒烟。

### 打包为独立可执行文件（可选）

程序已适配 `sys.frozen`，使用 PyInstaller 打包后，配置文件会与 `.exe` 同级生成：

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --windowed --onefile tool2path.py
# 产物：dist\tool2path.exe
```

> 直接使用 `python` / `pip` 命令安装到全局环境同样可行，但虚拟机环境更干净、更易复现。

## 使用指南

启动后是「左报备库 — 中操作 — 右 PATH 总览」的三区界面。典型流程如下。

### 场景一：首次启用一个工具链

1. 左栏点「**＋ 报备新目录**」，粘贴或浏览选择入口目录（支持一行一个批量粘贴），例如 `C:\Program Files\nodejs`。
2. 确定后左栏出现该条目，配置文件末尾追加一行。
3. 左栏勾选该条目 → 点中栏「**移入 →**」，条目进入右栏 **用户级 PATH 底部**（此步只生成"待应用变更"，尚未写盘）。
4. 底部点「**应用**」（窗口保持打开）或「**确认**」（应用后关闭）→ 全量写回注册表并广播。
5. **新开的**终端 / 进程中该命令即可用（已打开的窗口需重启才能读到新 PATH）。

### 场景二：临时停用一组工具链（批量移出）

1. 右栏勾选 / 框选多个**报备行**（灰色【锚点】行不可选）。
2. 点中栏「**← 移出**」，二次确认后整组从 PATH 移除，并**按右栏显示顺序追加回配置文件末尾**（仍在报备库，随时可再移入）。
3. 点「应用」落盘。

### 场景三：用拖拽完成启用 / 停用

- **左 → 右**：把左栏条目直接拖到右栏某个插入位，**拖到哪落到哪** = 移入。
- **右 → 左**：把右栏报备行拖回左栏「报备库」= **拖回即移出**；落到具体行间隙则插入配置文件对应库位，落到空白处则追加到文件末尾。
- **左栏内拖拽**：调整报备库顺序，实时写回配置文件（**不需要**点应用）。
- **右栏内拖拽**：多选后可整组拖动到任意插入位，组内相对顺序不变。
- 单行微调可用行内 `▲` / `▼`。

### 场景四：手工编辑配置文件

1. 用任意编辑器打开程序同级的 `registered-paths.yaml`，增删 / 调整行序。
2. 回到程序，会提示「配置文件已被外部修改，是否重新载入？」，选择「重新载入」即可；也可随时点顶栏「**⟳ 重新载入配置**」。

### 快捷键与按钮

| 控件 | 作用 |
| --- | --- |
| `Ctrl+Z` | 撤销最近一组待应用变更（仅限待应用阶段，落盘后不可回滚） |
| `Ctrl+A` | 全选当前聚焦栏的可选项 |
| 顶栏「⟳ 重新载入配置」 | 重读 `registered-paths.yaml` 刷新报备库（保留待应用变更） |
| 顶栏「↻ 重读注册表」 | 以注册表为事实源重建右栏，并清空待应用变更 |
| 底栏「待应用 N 项」 | 预览 / 撤销某一组待应用变更 |
| 「应用」/「确认」/「退出」 | 应用并停留 / 应用并关闭 / 放弃未应用改动并退出 |
| 行内右键菜单 | 编辑、删除报备、移入、移出、上移 / 下移一格 |

### 关键提示

- **左栏顺序 ≠ PATH 顺序**：左栏只是报备库的整理顺序（写配置文件，即时生效）；真正影响命令解析的是右栏 PATH 顺序（需点「应用」）。
- **退出前请注意**：存在未应用的变更时退出会弹确认；配置文件的改动（报备 / 排序 / 移出回库）已即时保存，不受影响。
- **在新终端生效**：写回后已打开的终端不会自动刷新，请新开一个窗口；部分启动器 / IDE 需重启。

## 配置文件约定

`registered-paths.yaml` 位于**与程序同级的目录**（源码运行 = 脚本所在目录；打包运行 = `.exe` 所在目录），首次启动若不存在会自动创建。

```yaml
# Toolchain Path Manager - 已报备的工具链入口目录
# 每一行 = 一个入口目录；顺序 = 报备库内顺序；可手工编辑后在本软件中重新载入
- C:\Program Files\nodejs
- C:\Python312\Scripts
- D:\Ruby\bin
```

约定：

- 内容**仅为一个目录路径列表**，每行一项；支持 `#` 注释行与空行，`- ` 前缀可有可无。
- **不包含** id、名称、排序号、备注、时间戳等任何字段；界面显示名由路径末级自动派生（`C:\Program Files\nodejs` → `nodejs`）。
- 文件**行序 = 报备库顺序**，仅影响清单展示与批量移入的先后次序，与 PATH 生效顺序无关。
- **同目录唯一**：不区分大小写、忽略尾部空格与反斜杠（`C:\Go\bin` 与 `c:\go\bin\` 视为同一目录）。
- 编码为 UTF-8；界面写回只重写路径列表区并尽量保留头部注释，且**不会产生** `.bak` / `.tmp` 等临时文件。

## 设计规则（R0–R7）

实现严格围绕以下八条规则，任一新增功能都不得违反（自测脚本逐条覆盖）：

| 规则 | 名称 | 内容 |
| --- | --- | --- |
| **R0** | 配置文件即报备库 | `registered-paths.yaml` 是**唯一事实源**；界面增删改排全部写回该文件 |
| **R1** | 白名单与接管 | 只有报备过的路径才可移出 / 拖动 / 多选；报备即接管；未报备路径为只读锚点 |
| **R2** | 锚点不变 | 任何操作都不得改变未报备路径之间的相对顺序；落盘前自动断言 |
| **R3** | 库内自由排序 | 左栏拖拽排序直接写回配置文件，**不进入**待应用机制 |
| **R4** | 组序不变 | 批量操作把多选集合视为一组，组内相对顺序在移动前后保持不变 |
| **R5** | 右栏拖动规则 | 仅报备行可拖动；可整组落到任意插入位，或反向拖回左栏完成移出 |
| **R6** | 唯一性 | 同目录禁止重复报备（读取 / 写入双重去重）；移入时逐条判重跳过 |
| **R7** | 待应用与全量回写 | 右栏改动先进待应用（可撤销）；点「应用 / 确认」时一次性全量写回用户级 PATH 整键 |

### 注册表写入遵循 Microsoft 标准做法

- 键位固定为 `HKCU\Environment\Path`，**只写用户级**，绝不触碰 `HKLM` 或其他键；
- 读取时记录原始类型，写回时保持 `REG_EXPAND_SZ` / `REG_SZ` 不变，**不做类型转换**；
- 不对 `%VAR%` 做展开改写，按字面字符串原样写回；
- **不使用 `setx`**（它会把 `REG_EXPAND_SZ` 降级为 `REG_SZ`，并在约 1024 字符处截断）；
- 写入成功后广播 `WM_SETTINGCHANGE`（`lParam = "Environment"`），使新进程读到新值；
- 落盘为"整键全量写回"，有变化时只写一次，不留下任何临时文件。

## 常见问题解答（FAQ）

**Q1：改完之后当前终端还是找不到命令？**
写入成功后程序会广播 `WM_SETTINGCHANGE`，但**已经打开的进程不会自动刷新环境**。请新开一个终端；IDE、终端复用器（如 tmux）、部分启动器需要重启才能读到新 PATH。

**Q2：为什么有些路径我怎么点都选不中、拖不动？**
那些是**锚点**——未报备的系统原有路径（灰色【锚点】🔒 标记）。它们被刻意设计为只读，以保证顺序永不被软件改动。想管理它们，请先在左栏「＋ 报备新目录」里报备对应目录，报备后即"接管"为可管理项。

**Q3：报备一个本来就在 PATH 里的目录会发生什么？**
报备即接管：该行立刻变为可管理项，**值与位置保持不变**，因此不需要额外写盘，也不会重复追加一行。

**Q4：我直接改了 `registered-paths.yaml`，软件会覆盖我的改动吗？**
不会。程序检测到外部改动后会询问「是否重新载入？」，由你决定；选择「暂不」则保留界面当前状态，但此后继续在界面编辑会以界面为准覆盖文件。

**Q5：点了「应用」还能撤回吗？**
不能。撤销（`Ctrl+Z`）只在**待应用阶段**有效；一旦落盘就没有自动回滚。所以界面上有较多改动时，建议先点「应用」前用「待应用 N 项」预览一遍，再决定是否落盘。

**Q6：它会修改系统级 PATH 吗？需要管理员吗？**
不会，也不需要。本程序**只写用户级** `HKCU\Environment\Path`，普通权限即可，不涉及 UAC 提权。

**Q7：提示"PATH 超长"怎么办？**
Windows 对 PATH 有长度限制（程序以约 32000 字符为阈值预警）。超长时应选择「放弃该项」并精简条目（例如用目录软链接归档工具链），而不是强行写入，否则可能导致部分命令不可用。

**Q8：提示"R2 锚点断言失败"是什么情况？**
说明在你操作期间，PATH 已被外部程序（如某个安装器）改动，锚点顺序与快照不一致。请先点「**重读注册表**」以注册表为事实源重建，再重新操作。

**Q9：报备的目录被移动或删除了会怎样？**
会标黄提示「目录不存在」，但记录仍保留，方便你右键「编辑」一键重设路径，不会被静默丢弃。

**Q10：配置文件被我改坏了 / 误删了会怎样？**
解析失败时程序进入"配置未加载"**保护态**，禁止一切写 PATH 相关操作以免污染注册表，并提示出错行；文件误删则首次启动会自动重建一个空清单。建议把该文件纳入 Git / dotfiles 版本管理。

**Q11：非 Windows 能用吗？**
不能实际生效。程序可在非 Windows 上启动并预览界面，但注册表操作会走内存假实现，不会真正写入系统。

**Q12：为什么要用"待应用 + 全量写回"，而不是改一条写一条？**
因为 PATH 是一个整体字符串，逐条改写容易与外部的并发改动互相覆盖，也难以保证锚点顺序。集中一次性全量写回 + 落盘前断言，是更简单也更安全的模型。

   ```powershell
   .\.venv\Scripts\python.exe tests\selftest.py
   ```

   确保退出码为 `0`（全部通过）。涉及注册表写入的测试请使用内存 `FakeRegistry`，**不要**在测试中触碰真实 `HKCU`。

6. **提交 PR**：从最新 `main` 拉出分支，描述改动范围、验证方式与影响面，并关联相关 Issue。
